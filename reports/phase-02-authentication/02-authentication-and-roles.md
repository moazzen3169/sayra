## 1. Executive Summary & Discovered Roles

The Sayra platform implements **4 active frontend authentication boundaries** (and **5 backend actor/role scopes**):
1. **Guest (Unauthenticated)**: Public discovery & read-only browsing.
2. **Customer (`actorType: "CUSTOMER"`, normalized to `USER`)**: Passwordless phone OTP login (`/login` or `AuthModal`), stored in `localStorage` (`sayra_access_token`, `sayra_refresh_token`, `sayra_user_auth`) + cookies.
3. **Owner / Manager / Staff (`actorType: "USER"`, `role: "MANAGER" | "OWNER" | "STAFF"`, normalized to `MANAGER`)**: OTP/onboarding login (`/owner/new` or `/login`), scoped to `gamingCenterId`. *(Note: Backend supports `STAFF` CRUD and shifts under `/gamingCenters/:id/staff`, while frontend has no Staff management UI — Staff role navigation shares `/owner/*` via `AuthContext`.)*
4. **Platform Admin (`actorType: "PLATFORM_ADMIN"`, `ADMIN`/`SUPER_ADMIN`)**: Phone + password login at `/admin/login` (Tab 1), stored in `sessionStorage` (`sayra_admin_access_token`, `sayra_admin_refresh_token`, `sayra_admin_user_auth`).
5. **Blog Admin (Django Staff User)**: Username + password login at `/admin/login?tab=blog` (Tab 2), stored in `localStorage` (`sayra_blog_access_token`, `sayra_blog_refresh_token`).

### Critical & High Auth Issues Uncovered in Phase 2
1. **CRITICAL/HIGH — `/admin/blog` Auth Guard Bypass / Stale-Token Trap (`AdminLayout`)**: When unauthenticated (with expired/missing valid session) or logged in as a regular Customer (`09990001101`), visiting `/admin/blog` failed to redirect to `/admin/login`, rendering the Blog Admin CMS shell (`مدیریت وبلاگ و محتوا`). With a stale/persisted `localStorage.sayra_blog_access_token`, Customer users could view `/admin/blog` data; without a valid token, `/admin/blog` rendered and sent `GET /articles/` + `GET /categories/` failing with HTTP `403` without redirecting (`client.ts` only triggers `sayra:blog-auth-expired` on `401` / `TOKEN_NOT_VALID`, not `403`). Furthermore, unauthenticated `/admin/blog` redirects to `/admin/login` instead of `/admin/login?tab=blog`.
2. **HIGH — Customer Session Cleared Upon Visiting `/admin` (`resolveAuthScope` Bug)**: When logged in as Customer `09990001101` and navigating to `/admin` (which redirects to `/admin/login`) or `/admin/blog`, `AuthContext` runs `/auth/me` while `window.location.pathname` starts with `/admin`. `resolveAuthScope()` in `src/lib/api/client.ts` overrides scope to `"admin"`, omits the Customer Bearer token, receives `401`, and wipes the Customer's session on return to `/profile`.
3. **HIGH — Platform Admin Email Login Fails (`401 Invalid credentials`)**: `/admin/login` labels the identifier input `"شماره موبایل یا ایمیل"` and `authService.loginPlatformAdminWithEmail` sends `{ email, phone }` with the email in both fields. However, backend `POST /api/v1/auth/platform-admin/login` (`auth.validators.ts` + `auth.controller.ts` + `auth.repository.ts`) ONLY accepts `phone` (`findPlatformAdminByPhone`). Logging in with `moazzenhadi46@gmail.com` fails with `401`, whereas `09396821435` succeeds with `200`.
4. **HIGH — Missing Logout Action in Admin & Blog Admin UI**: Neither `AdminSidebar.tsx` nor `AdminHeader.tsx` provides a logout button anywhere in `/admin/*`, trapping logged-in admins in their session unless they manually clear browser storage.
5. **MEDIUM — Deprecated Auth Endpoints & Raw Debug Error Messages**: Customer OTP uses deprecated `/auth/customer/otp/request` and `/auth/customer/otp/verify` (returning `X-API-Deprecation-Warning`), `ENDPOINTS.auth.userOtpLogin` points to non-existent `/auth/customer/login/otp`, Platform Admin login renders untranslated `"Invalid credentials"`, and Customer wrong-OTP displays raw technical suffix `"[401 APP_ERROR: Invalid or expired OTP.]"`.
